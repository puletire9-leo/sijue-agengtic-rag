# 踩坑记录

## 坑 1: `sentence-transformers` 导入失败

**现象：** 容器反复重启，日志报 `ImportError: Could not import sentence_transformers`

**原因：** `embedding.py` 使用了 `langchain_huggingface.HuggingFaceEmbeddings`，它依赖 `sentence-transformers` 包，但 requirements.txt 里没写。

**教训：** 所有直接/间接依赖都必须显式写入 requirements.txt。

```txt
langchain-huggingface>=0.1
sentence-transformers>=3.0
```

## 坑 2: 模块级实例化导致 import 即崩溃

**现象：** 后端在 import 阶段就报错，无法启动。

**原因：** `embedding.py` 第 219 行：

```python
embedding_service = EmbeddingService()  # ← 模块加载时立即执行
```

`EmbeddingService.__init__()` 中调用了 `HuggingFaceEmbeddings(model_name=...)` 加载模型。如果依赖缺失或模型路径不对，整个应用无法 import。

**教训：** 模块级实例化会导致 import 时就触发重操作。如果必须这样做，确保 try/except 包裹并给出清晰错误信息。

## 坑 3: Docker 容器内无法访问 huggingface.co

**现象：** `FileNotFoundError: Path /root/.cache/huggingface/...`

**原因：** 国内网络无法访问 huggingface.co，模型下载失败。

**解决：**

```yaml
environment:
  HF_ENDPOINT: https://hf-mirror.com     # HuggingFace 国内镜像
```

更好的方案是本地下载模型后挂载进容器（见 [02-模型下载与本地挂载](./02-模型下载与本地挂载.md)）。

## 坑 4: Docker Compose 网络命名冲突

**现象：**
```
a network with name supermew exists but was not created for project "agentic-rag"
```

**原因：** 同一个 compose 文件在不同目录/不同项目名下运行时，网络名可能冲突。

**影响：** 目前只是 warning，不影响功能。如需消除：

```yaml
networks:
  default:
    name: supermew
    external: true  # 使用外部已存在的网络
```

## 坑 5: 健康检查等待模型加载

**现象：** 容器启动后 health check 持续 `starting` 1-2 分钟才变 `healthy`。

**原因：** 首次启动时模型加载需要时间，但健康检查的 `start-period` 太短：

```yaml
HEALTHCHECK --interval=30s --timeout=10s --start-period=10s --retries=3
```

**建议：**
- `start-period` 设为 60s（给模型加载留足时间）
- `retries` 设为 5 次（避免因模型加载慢而被标记为 unhealthy）

## 坑 6: `HF_HOME` 和模型路径

如果只设 `HF_HOME` 不设 `EMBEDDING_MODEL` 为绝对路径，HuggingFace 仍会尝试从网络下载模型。

**正确做法：** 同时设置：

```yaml
EMBEDDING_MODEL: /app/models/bge-m3    # 本地绝对路径
HF_HOME: /app/models                    # 缓存目录
```

## 坑 7: `pytorch/pytorch` 镜像在国内 403

daocloud.io Docker 镜像站对 `pytorch/pytorch` 镜像返回 403 Forbidden。

**解决：** 使用标准 `python:3.11-slim` + 手动 `pip install torch --index-url https://download.pytorch.org/whl/cpu`。

## 坑 8: `unstructured` 包的额外依赖

`unstructured` 解析不同文件格式需要额外包：

| 格式 | 额外依赖 |
|------|---------|
| PDF | `pypdf` |
| Word | `docx2txt` |
| PPT | `python-pptx` |

如果缺少 `python-pptx`，解析 PPT 时会安静失败或报错，不会在 pip install 时提示。

## 坑 9: 向量导入性能瓶颈

**现象：** 文档上传时"向量化入库"阶段卡顿极久。

**原因：** 旧 `milvus_writer.py` 每个 batch（50 条）单独调用一次模型推理。1000 条 chunk 就是 20 次模型调用。

**解决：** 改为一次性生成所有密集向量，再分批写入 Milvus。详见项目源码 `backend/milvus_writer.py`。

**效果：** 密集向量编码时间从 O(N_batches × model_overhead) 降为 O(1 × model_overhead)。
