# 镜像构建与缓存

## 1. 慎用 `--no-cache`

`docker compose build --no-cache` 会强制重跑所有层，包括 apt-get、pip install torch 等本可缓存的内容。

**正确做法：** 去掉 `--no-cache`，Docker 会自动复用未变更的层。

只在以下情况用 `--no-cache`：
- 怀疑缓存损坏
- 基础镜像或 apt 源有更新需要拉取

## 2. 层顺序决定缓存效率

`Dockerfile.base` 的设计：

```dockerfile
FROM python:3.11-slim          # ← 基础层，基本不变
RUN apt-get install ...          # ← 系统依赖，很少变
RUN pip install torch (CPU版)    # ← 大体积但很少变
COPY requirements.txt .          # ← 依赖清单
RUN pip install -r requirements  # ← 应用依赖，偶尔变
```

**原则：变化频率越高的放越后面。** 这样改 requirements.txt 时，前 3 层全部命中缓存，只需重跑最后一层。

## 3. PyTorch CPU 版节省 2.3GB

**坑：** `sentence-transformers` 依赖 `torch`，pip 默认拉取 CUDA 版（~2.5GB），下载极慢。

**解决：** 在 `Dockerfile.base` 中预装 PyTorch CPU 版作为独立层：

```dockerfile
RUN pip install --no-cache-dir torch --index-url https://download.pytorch.org/whl/cpu
```

CPU 版仅 ~180MB，且后续 `pip install sentence-transformers` 会检测到 torch 已安装，不再重复下载。

## 4. 别用 `pytorch/pytorch` 镜像（国内）

`FROM pytorch/pytorch:2.5.1-python3.11-slim` 在国内 Docker 镜像站（daocloud.io）返回 403。

直接用 `FROM python:3.11-slim` + 手动 `pip install torch`。

## 5. Docker Compose 并行构建的坑

`docker compose build` 默认并行构建所有服务。如果 `backend` 依赖 `python-base` 镜像，可能 backend 在 python-base 完成前就开始构建，导致使用旧镜像。

**解决：** 先单独构建基础镜像，再构建应用镜像：

```powershell
docker compose build python-base
docker compose build backend
docker compose up -d backend
```
