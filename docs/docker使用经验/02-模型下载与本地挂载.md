# 模型下载与本地挂载

## 问题：容器内下载模型极慢

HuggingFace 模型（如 BAAI/bge-m3 ~2.2GB）在容器内下载：
1. 每次重建容器都要重新下载
2. 国内访问 huggingface.co 经常超时
3. 下载失败会导致容器启动卡死

## 解决方案：宿主机下载 + 目录挂载

### Step 1: 宿主机下载模型

```powershell
# 方式 A: huggingface-cli（已废弃，改用 hf）
pip install huggingface_hub
& "C:\Users\Admin\AppData\Roaming\Python\Python314\Scripts\hf.exe" download BAAI/bge-m3 --local-dir "d:\项目\agentic rag\SuperMew\models\bge-m3"

# 方式 B: modelscope（国内更快）
pip install modelscope
& "C:\Users\Admin\AppData\Roaming\Python\Python314\Scripts\modelscope.exe" download --model BAAI/bge-m3 --local_dir "d:\项目\agentic rag\SuperMew\models\bge-m3"
```

### Step 2: docker-compose 挂载模型目录

```yaml
services:
  backend:
    environment:
      EMBEDDING_MODEL: /app/models/bge-m3    # 直接指向本地路径
      HF_HOME: /app/models                    # HuggingFace 缓存目录
      HF_ENDPOINT: https://hf-mirror.com     # 国内镜像（备用）
    volumes:
      - ../../models:/app/models              # 宿主机 → 容器
```

**关键：`EMBEDDING_MODEL` 设为容器内的本地路径而非模型名。** 这样 sentence-transformers 直接从本地加载，不触发任何网络请求。

### Step 3: 验证

启动后日志应显示：
```
Loading weights: 100%|██████████| 391/391 [00:00<00:00, 9900.05it/s]
```
加载速度 ~1 秒（vs 网络下载 2GB 需要数分钟）。

## 路径注意事项

docker-compose.yml 中的相对路径基于 compose 文件所在目录：

```yaml
# compose 文件位置: agentic-rag/docker-compose.yml
volumes:
  - ../data:/app/data        # → SuperMew/SuperMew/data
  - ../../models:/app/models # → SuperMew/models
```

`..` 往上一级。需要几级 `..` 取决于文件相对于目标目录的深度。

## 附录：BAAI/bge-m3 模型文件清单

下载后目录应包含：
```
models/bge-m3/
├── pytorch_model.bin       (~2.12GB，PyTorch 权重)
├── model.onnx               (724KB，ONNX 模型结构)
├── model.onnx_data          (~2.11GB，ONNX 权重，可用于 ONNX Runtime 加速)
├── tokenizer.json           (~17MB)
├── sentencepiece.bpe.model  (~5MB)
├── config.json
├── modules.json
└── ...
```

ONNX 文件已包含在内，后续可切换 ONNX Runtime 加速 CPU 推理（比 PyTorch 快 2-3 倍）。
