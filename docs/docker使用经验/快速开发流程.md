# 快速开发流程

## 原则
- **不本地装依赖**：用 Docker 容器已有环境，不 `uv run`（会下载几百MB CUDA 包）
- **不 docker build**：除非最终部署，开发阶段不构建镜像
- **代码挂载 + 热重载**：改代码容器自动重启，浏览器即时刷新

## 后端（SuperMew）

docker-compose.yml 已配置：
```yaml
app:
  volumes:
    - ./backend:/app/backend          # 代码挂载
  command: uvicorn app:app --host 0.0.0.0 --port 8000 --reload  # 热重载
```

改 `backend/` 下任何 .py 文件 → 容器 2-3 秒自动重启。

## 前端（Open WebUI）

Vite dev server 运行在本地，端口 5173 或 5174。

改 `open-webui-main/src/` 下任何 .svelte/.ts 文件 → Vite HMR 即时刷新浏览器。

**不需要重启 Vite**，HMR 自动检测文件变更。

## Open WebUI 后端代理

docker-compose.yml 已配置 volume mount：
```yaml
open-webui:
  volumes:
    - ./open-webui-main/backend/open_webui/utils/middleware.py:/app/backend/open_webui/utils/middleware.py
    - ./open-webui-main/backend/open_webui/routers/openai.py:/app/backend/open_webui/routers/openai.py
    - ./open-webui-main/backend/open_webui/routers/files.py:/app/backend/open_webui/routers/files.py
    - ./open-webui-main/backend/open_webui/routers/starlink.py:/app/backend/open_webui/routers/starlink.py
```

改这些文件 → `docker compose restart open-webui` 生效（Open WebUI 没有 --reload）。

## 常见问题

### 前端改了没反应
- 检查 Vite 是否在运行：`ps aux | grep vite`
- 如果 Vite 没运行：`cd open-webui-main && npm run dev`
- WSL 环境下 inotify 可能不可靠，重启 Vite：`pkill -f "vite dev" && npm run dev`

### 后端改了没反应
- 检查容器是否在运行：`docker ps | grep app`
- 检查日志：`docker logs supermew-app --tail 20`
- 重启容器：`docker compose restart app`

### Open WebUI 后端改了没反应
- 需要手动重启：`docker compose restart open-webui`
- 因为没有 --reload，必须重启才能生效

### 上传文件 401/405
- 检查路由是否正确：`curl -s -X POST http://localhost:13000/api/v1/files/starlink/documents/upload -H "Authorization: Bearer test"`
- 405 = 路由不存在，检查 files.py 是否有对应 @router.post
- 401 = 认证失败，正常（用的是假 token）
