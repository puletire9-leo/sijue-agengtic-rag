# SuperMew Agent 功能设计

> 最后更新：2026-05-31

---

## 一、Agent 核心架构

SuperMew 的 Agent 层基于 LangChain Agent + LangGraph StateGraph 双层架构：

- **LangChain Agent**（`agent.py`）：外层 Agent，负责工具调用、记忆注入、循环检测
- **LangGraph StateGraph**（`agentic_rag/graph.py`）：内层 RAG 管线，18 节点有向图

### 1.1 Agent 调用链路

```
用户消息 → agent.py
  ├── 加载对话历史（分页 + 增量保存）
  ├── 上下文压缩（token > 64000 时触发 5 阶段压缩）
  ├── 记忆注入（3 层记忆 → SystemMessage）
  ├── 循环检测（_is_stuck + attempt_loop_recovery）
  └── agent.invoke(recursion_limit=25)
       ├── search_knowledge_base() → agentic_rag/graph.py
       ├── get_current_weather() → 天气查询
       ├── web_search() → DuckDuckGo fallback
       └── 其他工具...
```

### 1.2 LLM 3 层路由

| 层级 | 模型 | 用途 | 配置 |
|------|------|------|------|
| Tier 1 | 强力模型 | 生成回答、复杂推理 | `MODEL` + `ARK_API_KEY` |
| Tier 2 | 中等模型 | 文档评分、置信评估 | `GRADE_MODEL`（回退到 Tier 1）|
| Tier 3 | 轻量模型 | 快速路径、查询重写、实体提取 | `FAST_MODEL`（回退到 Tier 1）|

每个层级使用 `TrackedLLM` 包装，自动记录 token 数量和估算成本。线程安全的双重检查锁懒加载。

## 二、工具系统

### 2.1 内置工具

| 工具 | 文件 | 功能 |
|------|------|------|
| `search_knowledge_base` | `tools.py` | 知识库检索（触发 RAG 管线）|
| `get_current_weather` | `tools.py` | 天气查询（高德 API）|
| `web_search` | `builtin_tools/web_search.py` | 网页搜索（DuckDuckGo）|
| `memory_save` | `builtin_tools/memory_tool.py` | 保存记忆 |
| `memory_recall` | `builtin_tools/memory_tool.py` | 回忆记忆 |
| `clarify_question` | `builtin_tools/clarify_tool.py` | 澄清用户问题 |
| `list_knowledge_sources` | `builtin_tools/knowledge_sources.py` | 列出知识源 |
| `search_session_history` | `builtin_tools/session_search.py` | 搜索会话历史 |

### 2.2 工具调用防护

- **调用次数限制**：每次对话最多 1 次 `search_knowledge_base`（ContextVar 隔离）
- **工具护栏**：`core/tool_guardrails.py` 检查工具调用安全性

### 2.3 MCP 客户端

`tool_system/mcp_client.py` 支持 Model Context Protocol：
- **stdio 传输**：子进程通信（本地 MCP 服务器）
- **SSE 传输**：HTTP 远程 MCP 服务器

## 三、记忆系统

### 3.1 3 层记忆架构

| 层级 | Provider | 存储 | 召回方式 | 保留期 |
|------|----------|------|---------|--------|
| Layer 0 | `SessionProvider` | Redis | 字符 bigram 重叠 | 24h TTL |
| Layer 1 | `ShortTermProvider` | PostgreSQL | ILIKE 关键词 | 30 天 |
| Layer 2 | `LongTermProvider` | PostgreSQL + 向量 | 语义检索 | 永久 |

### 3.2 记忆注入流程

`memory_injector.py` 在每次对话前：
1. 查询 3 层记忆，按相关性排序
2. 构建记忆上下文文本
3. 注入为 `SystemMessage` 前置

### 3.3 情节记忆

`core/episodic_memory.py` 记录成功的查询→文档映射，用于检索提权：
- 记录：`record_success(query, doc_filenames)`
- 查询：`get_boosts(query)` → 返回文档加权因子

### 3.4 文档摘要索引

`document_summary.py` 为每个文档生成 LLM 摘要 + topic 倒排索引：
- 上传时自动生成摘要
- 检索时用于文档路由（章节过滤）

## 四、上下文压缩

`core/context_compressor.py` 实现 5 阶段压缩：

| 阶段 | 功能 |
|------|------|
| 1. Token 估算 | 估算当前上下文 token 数 |
| 2. 消息筛选 | 保留最近 N 条 + 系统消息 |
| 3. 历史摘要 | LLM 生成旧消息摘要 |
| 4. 中间压缩 | 对中间消息做二次压缩 |
| 5. 重组装 | 拼接摘要 + 保留消息 |

## 五、安全机制

### 5.1 双护栏

- **查询护栏**：10 种注入模式 + LLM 语义二次判断
- **输出护栏**：6 种输出风险 + LLM 语义判断

### 5.2 预算管理

- 最大迭代 5 次，重试 3 次，宽限 1 次
- 预算耗尽时返回降级回答

### 5.3 循环检测

`core/loop_detector.py` 检测 Agent 是否陷入死循环：
- 消息重复检测
- 自动恢复：注入提示打破循环

### 5.4 3 层限流

| 层级 | 实现 | 用途 |
|------|------|------|
| Agent 级 | IterationBudget | 防单会话死循环 |
| 用户级 | SlidingWindowRateLimiter（Redis）| 防单用户恶意消耗 |
| 全局级 | TokenBucketRateLimiter（Redis）| 保护 LLM API |

## 六、可观测性

### 6.1 Prometheus 指标

13 个指标覆盖：HTTP 请求、LLM 调用、RAG 检索、预算耗尽、文档上传、记忆召回、护栏拦截、活跃连接、限流。

### 6.2 OpenTelemetry

可选启用（`OTEL_ENABLED=true`），支持 OTLP gRPC 导出。

### 6.3 结构化日志

可选启用（`STRUCTURED_LOG=true`），JSON 格式 + `request_id` 全链路串联。

### 6.4 LLM 成本追踪

TrackedLLM 自动记录每次调用的 token 数和估算成本。

## 七、评测体系

### 7.1 检索层指标

`evaluation/metrics.py`：Hit Rate, MRR, Recall, Precision, NDCG（支持 @3, @5, @10）

### 7.2 生成层指标

`evaluation/ragas_eval.py`：RAGAS 集成（Faithfulness, Answer Relevancy, Context Precision/Recall）

### 7.3 评测 API

| 端点 | 说明 |
|------|------|
| `/eval/run` | 运行完整评测 |
| `/eval/report/{run_id}` | 获取报告 |
| `/eval/history` | 历史对比 |
| `/eval/dataset` | Golden Dataset CRUD |

### 7.4 反馈闭环

| 端点 | 说明 |
|------|------|
| `/feedback` | 提交反馈 |
| `/feedback/stats` | 反馈统计 |
| `/feedback/bad-cases` | 差评案例 |
