**问题**: SuperMew 的引用被 `format_citations_as_text()` 转为纯文本追加到回答末尾，Open WebUI 的交互式引用卡片无法展示。

**方案**: 在 OpenAI 响应中添加 `sources` 字段，格式与 Open WebUI 的 citation 格式对齐。

Open WebUI 期望的 sources 格式:
```json
{
  "sources": [{
    "source": {"name": "filename.pdf", "id": "file_id"},
    "document": ["chunk text..."],
    "metadata": [{"source": "filename.pdf", "page": 3}]
  }]
}
```

**改动**:
- `openai_adapter.py`: 新增 `format_citations_as_sources()` 函数
- `openai_compatible.py`: 流式响应结束后发送 sources 数据，非流式响应附加 sources 字段

#### 0.2 RAG 步骤通过 reasoning_content 展示（P0）

**问题**: RAG 思考步骤（检索/评估/重写）通过 `_RagStepProxy` 捕获但不通过 OpenAI 协议传输，用户看不到处理过程。

**修改文件**: `backend/routers/openai_compatible.py`

**方案**: 利用 Open WebUI 对 `reasoning_content` 的支持，将 RAG 步骤作为 thinking 内容流式输出。

Open WebUI 的 reasoning 格式:
```json

```

**改动**:
- `_stream_response` 中，从 `_RagStepProxy` 捕获的 RAG 步骤转换为 `reasoning_content` chunk
- 在第一个 content chunk 之前，先发送所有已收集的 RAG 步骤
- 同时支持实时推送（步骤执行时立即发送 reasoning chunk）

#### 0.3 反馈数据同步（P1）

```python
# backend/evaluation/metrics.py
def hit_rate_at_k(retrieved: list, expected: list, k: int) -> float:
    """Hit Rate@k: 前 k 个结果中是否包含正确文档。"""
    top_k = retrieved[:k]
    return 1.0 if any(doc in expected for doc in top_k) else 0.0

def mrr_at_k(retrieved: list, expected: list, k: int) -> float:
    """MRR@k: 第一个正确结果的排名倒数。"""
    for i, doc in enumerate(retrieved[:k]):
        if doc in expected:
            return 1.0 / (i + 1)
    return 0.0

def recall_at_k(retrieved: list, expected: list, k: int) -> float:
    """Recall@k: 检索到的相关文档占全部相关文档的比例。"""
    top_k = set(retrieved[:k])
    expected_set = set(expected)
    if not expected_set:
        return 1.0
    return len(top_k & expected_set) / len(expected_set)

def precision_at_k(retrieved: list, expected: list, k: int) -> float:
    """Precision@k: 前 k 个结果中相关文档的比例。"""
    top_k = retrieved[:k]
    if not top_k:
        return 0.0
    return sum(1 for doc in top_k if doc in expected) / len(top_k)

def ndcg_at_k(retrieved: list, expected: list, k: int) -> float:
    """NDCG@k: 归一化折损累计增益。"""
    import math
    dcg = sum(1.0 / math.log2(i + 2) for i, doc in enumerate(retrieved[:k]) if doc in expected)
    idcg = sum(1.0 / math.log2(i + 2) for i in range(min(len(expected), k)))
    return dcg / idcg if idcg > 0 else 0.0
```

#### 2.1 语义缓存

**新建文件**: `backend/core/semantic_cache.py`

```python
class SemanticCache:
    """基于 Milvus 的语义缓存。"""

    def __init__(self, collection_name="semantic_cache", threshold=0.95, ttl=86400):
        self.collection = collection_name
        self.threshold = threshold  # cosine similarity 阈值
        self.ttl = ttl

    def get(self, query_embedding: list) -> Optional[dict]:
        """语义相似度搜索缓存，命中返回缓存答案。"""
        results = milvus_search(self.collection, query_embedding, top_k=1)
        if results and results[0]["score"] >= self.threshold:
            return results[0]["metadata"]
        return None

    def set(self, query_embedding: list, answer: dict):
        """缓存查询答案。"""
        milvus_insert(self.collection, query_embedding, metadata=answer)

    def invalidate_by_doc(self, filename: str):
        """文档更新时清除相关缓存。"""
        milvus_delete(self.collection, filter=f'source == "{filename}"')
```

```python
def _extract_tables(pdf_path: str) -> list[dict]:
    """提取 PDF 表格并转为 Markdown。"""
    import pdfplumber
    tables = []
    with pdfplumber.open(pdf_path) as pdf:
        for page_num, page in enumerate(pdf.pages):
            for table in page.extract_tables():
                md = _table_to_markdown(table)
                tables.append({
                    "text": md,
                    "page_number": page_num + 1,
                    "type": "table",
                })
    return tables

def _table_to_markdown(table: list[list]) -> str:
    """将表格数据转为 Markdown 格式。"""
    if not table:
        return ""
    header = "| " + " | ".join(str(c or "") for c in table[0]) + " |"
    sep = "| " + " | ".join("---" for _ in table[0]) + " |"
    rows = ["| " + " | ".join(str(c or "") for c in row) + " |" for row in table[1:]]
    return "\n".join([header, sep] + rows)
```

**依赖**: `pdfplumber`

#### 3.3 语义分块

**新建文件**: `backend/core/semantic_chunker.py`

**实现**:
```python
class SemanticChunker:
    """基于 embedding 相似度的语义分块。"""

    def __init__(self, similarity_threshold=0.5, min_chunk_size=100, max_chunk_size=1000):
        self.threshold = similarity_threshold
        self.min_size = min_chunk_size
        self.max_size = max_chunk_size

    def split(self, text: str, embeddings_model) -> list[str]:
        """按语义边界切分文本。"""
        sentences = _split_sentences(text)
        if len(sentences) <= 1:
            return [text]

        # 计算相邻句子的相似度
        vecs = embeddings_model.embed_documents(sentences)
        chunks = []
        current = [sentences[0]]

        for i in range(1, len(sentences)):
            sim = cosine_similarity(vecs[i-1], vecs[i])
            current_text = " ".join(current)

            if sim < self.threshold and len(current_text) >= self.min_size:
                chunks.append(current_text)
                current = [sentences[i]]
            else:
                current.append(sentences[i])

            if len(" ".join(current)) >= self.max_size:
                chunks.append(" ".join(current))
                current = []

        if current:
            chunks.append(" ".join(current))

        return chunks
```

```python
def _compute_file_hash(file_path: str) -> str:
    """计算文件 SHA256。"""
    import hashlib
    with open(file_path, "rb") as f:
        return hashlib.sha256(f.read()).hexdigest()

def upload_document(file_path: str, filename: str):
    """上传文档，支持增量更新。"""
    new_hash = _compute_file_hash(file_path)
    existing_hash = get_document_hash(filename)

    if new_hash == existing_hash:
        return {"status": "skipped", "reason": "content unchanged"}

    # 内容变更：删除旧 chunks 并重新索引
    delete_document_chunks(filename)
    chunks = load_and_split(file_path)
    index_chunks(chunks)
    save_document_hash(filename, new_hash)
    return {"status": "indexed", "chunks": len(chunks)}
```

### 复查维度与方法

| 维度 | 复查方法 | 频率 | 责任人 |
|------|---------|------|-------|
| **检索质量** | 运行 RAGAS 评测，检查 Hit Rate@5 ≥ 95%, MRR@5 ≥ 0.8 | 每次代码变更 | 开发者 |
| **生成质量** | 运行 RAGAS 评测，检查 Faithfulness ≥ 90%, Answer Relevancy ≥ 0.8 | 每次代码变更 | 开发者 |
| **幻觉率** | 抽检 100 条回答，计算幻觉比例 ≤ 5% | 每周 | QA |
| **响应时间** | Prometheus P99 ≤ 5s | 持续监控 | 运维 |
| **错误率** | Prometheus 错误率 ≤ 1% | 持续监控 | 运维 |
| **用户满意度** | 反馈数据满意度 ≥ 85% | 每周 | PM |
| **安全护栏** | 运行 guardrails 测试集，拦截率 ≥ 99% | 每次变更 | 安全 |
| **并发稳定性** | Locust 10 并发压测，无报错 | 每次发布 | QA |

### 自动化复查流程

```
代码提交 → GitHub Actions CI
  ├─ Lint (ruff)
  ├─ Unit Tests (pytest)
  ├─ Integration Tests (pytest -m integration)
  └─ RAGAS Evaluation (golden dataset)
       ├─ 检索层指标 → 不达标则阻断合并
       └─ 生成层指标 → 不达标则告警

发布前:
  ├─ Locust 负载测试 → P99 < 5s
  ├─ 安全护栏测试集 → 拦截率 > 99%
  └─ 人工抽检 10 条回答 → 无幻觉
```

### Bad Case 复查流程

1. 用户提交 👎 或低评分 → 自动归入 bad case 列表
2. 每周 review bad cases，分类:
   - **检索问题**: 查询未命中正确文档 → 优化 embedding / 查询重写
   - **生成问题**: 检索正确但回答错误 → 优化 prompt / 模型
   - **理解问题**: 查询意图理解错误 → 优化 fast_path / decide_retrieval
3. 将 bad case 转化为 Golden Dataset 新条目，形成闭环

## 六、风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| RAGAS 依赖与现有 LangChain 版本冲突 | 中 | 高 | 使用独立评测容器，与主服务隔离 |
| OCR 准确率不稳定（中文扫描件） | 高 | 中 | 作为可选功能，配置开关控制；提供人工校正入口 |
| 语义缓存误命中导致返回错误答案 | 低 | 高 | 阈值设为 0.95 高阈值；提供手动失效 API |
| 评测成本高（大量 LLM 调用） | 中 | 中 | 使用 lightweight model 做评估；限制批次大小 |
| 表格提取格式丢失 | 中 | 中 | Markdown 格式保留结构；提供人工校验 |
| CI 流水线构建时间长 | 中 | 低 | 使用缓存（uv cache, Docker layer cache）|
