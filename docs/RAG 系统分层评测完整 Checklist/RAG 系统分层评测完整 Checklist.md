RAG 系统分层评测完整 Checklist
# RAG系统分层评测完整Checklist（可直接落地）
## 一、评测前置准备
| 检查项 | 完成状态 | 说明 |
|--------|----------|------|
| 构建评测数据集 | ☐ | 至少包含50-100个覆盖不同难度的真实用户问题 |
| 准备标准答案集 | ☐ | 每个问题对应1-2个人工标注的标准答案 |
| 准备参考上下文集 | ☐ | 每个问题对应应该被检索到的正确文档片段 |
| 确定评测环境 | ☐ | 与生产环境一致的模型、向量数据库和硬件配置 |
| 记录系统版本 | ☐ | 记录RAG系统的所有组件版本（嵌入模型、大模型、分块策略等） |

## 二、第一层：检索层评测（地基）
### 核心指标
| 指标名称 | 定义 | 计算方法 | 推荐工具 | 合格标准 |
|----------|------|----------|----------|----------|
| **Hit Rate@k** | 前k个检索结果中至少包含一个正确文档片段的比例 | `命中次数 / 总问题数` | Ragas, LangChain, LlamaIndex | Hit Rate@3 ≥ 85%<br>Hit Rate@5 ≥ 95% |
| **MRR@k** | 第一个正确文档片段在检索结果中的排名倒数的平均值 | `Σ(1/第一个正确结果的排名) / 总问题数` | Ragas, LangChain, LlamaIndex | MRR@3 ≥ 0.7<br>MRR@5 ≥ 0.8 |
| **Recall@k** | 所有相关文档片段中被检索到的比例 | `检索到的相关文档数 / 总相关文档数` | Ragas, Elasticsearch | Recall@5 ≥ 80%<br>Recall@10 ≥ 90% |
| **Precision@k** | 前k个检索结果中相关文档片段的比例 | `检索到的相关文档数 / k` | Ragas, Elasticsearch | Precision@3 ≥ 70%<br>Precision@5 ≥ 60% |
| **NDCG@k** | 归一化折损累计增益，考虑了相关文档的排序质量 | `DCG@k / IDCG@k` | Ragas, Elasticsearch | NDCG@5 ≥ 0.75 |

### 检索层专项检查
- [ ] 不同长度问题的检索效果对比
- [ ] 同义词、近义词问题的检索效果
- [ ] 多跳问题的检索效果
- [ ] 长文档的检索效果
- [ ] 新增文档的检索时效性

## 三、第二层：生成层评测（核心）
### 核心指标
| 指标名称 | 定义 | 计算方法 | 推荐工具 | 合格标准 |
|----------|------|----------|----------|----------|
| **忠实度(Faithfulness)** | 生成答案是否严格基于检索上下文，无幻觉内容 | `答案中基于上下文的陈述数 / 答案中总陈述数` | Ragas, DeepEval, LangChain | ≥ 90% |
| **答案相关性(Answer Relevance)** | 生成答案是否直接回答了用户的问题 | 大模型评分(0-1分) | Ragas, Promptfoo | ≥ 0.8 |
| **上下文相关性(Context Relevance)** | 检索到的上下文是否与问题相关 | `上下文中与问题相关的句子数 / 上下文总句子数` | Ragas | ≥ 0.7 |
| **事实正确性(Correctness)** | 生成答案中的事实信息是否准确 | 与标准答案对比评分(0-1分) | Ragas, 人工评估 | ≥ 0.85 |
| **完整性(Completeness)** | 生成答案是否涵盖了问题的所有方面 | 与标准答案对比评分(0-1分) | 人工评估, 大模型评分 | ≥ 0.8 |
| **简洁性(Conciseness)** | 生成答案是否简洁明了，无冗余信息 | 人工评估(0-1分) | 人工评估 | ≥ 0.7 |

### 生成层专项检查
- [ ] 答案是否包含无关信息
- [ ] 答案是否存在自相矛盾
- [ ] 答案是否正确引用了上下文来源
- [ ] 答案是否避免了过度泛化
- [ ] 答案的语气和风格是否符合要求

## 四、第三层：端到端评测（整体）
### 核心指标
| 指标名称 | 定义 | 计算方法 | 推荐工具 | 合格标准 |
|----------|------|----------|----------|----------|
| **问题解决率** | 用户问题得到有效解决的比例 | `解决的问题数 / 总问题数` | 人工评估, 业务数据 | ≥ 85% |
| **幻觉率** | 生成答案中出现幻觉内容的问题比例 | `出现幻觉的问题数 / 总问题数` | Ragas, 人工抽查 | ≤ 5% |
| **平均响应时间** | 从用户提问到得到完整答案的平均时间 | `总响应时间 / 总请求数` | 自定义脚本, Prometheus | ≤ 3秒 |
| **吞吐量** | 系统每秒能处理的请求数 | `总请求数 / 总时间` | Locust, JMeter | 根据业务需求确定 |
| **错误率** | 系统处理请求时发生错误的比例 | `错误请求数 / 总请求数` | 监控系统 | ≤ 1% |

### 端到端专项检查
- [ ] 高并发场景下的系统稳定性
- [ ] 大文档问答的效果和性能
- [ ] 多轮对话的上下文连贯性
- [ ] 敏感问题的处理能力
- [ ] 异常输入的鲁棒性

## 五、第四层：业务层评测（落地）
### 核心指标
| 指标名称 | 定义 | 计算方法 | 推荐工具 | 合格标准 |
|----------|------|----------|----------|----------|
| **人工转接率** | 需要人工介入处理的问题比例 | `人工转接数 / 总问题数` | 客服系统 | ≤ 15% |
| **用户满意度** | 用户对答案的满意程度 | `满意用户数 / 参与评价用户数` | 用户反馈系统 | ≥ 85% |
| **单次问答成本** | 平均每次问答的token消耗和计算成本 | `总成本 / 总问答数` | 云平台账单, 自定义统计 | 根据业务预算确定 |
| **系统可用性** | 系统正常运行时间的比例 | `正常运行时间 / 总时间` | 监控系统 | ≥ 99.9% |
| **知识库更新效率** | 新增知识到系统可用的时间 | `知识更新完成时间 - 知识提交时间` | 自定义统计 | ≤ 1小时 |

### 业务层专项检查
- [ ] 系统是否符合数据安全和隐私要求
- [ ] 知识库的可维护性和可扩展性
- [ ] 系统的可监控性和可调试性
- [ ] 与现有业务系统的集成效果
- [ ] 系统的ROI（投资回报率）

## 六、常用评测工具对比
| 工具名称 | 开源 | 核心优势 | 适用场景 |
|----------|------|----------|----------|
| **Ragas** | ✅ | 专为RAG设计，支持所有核心指标，自动化程度高 | 大多数RAG系统评测 |
| **DeepEval** | ✅ | 支持更多自定义指标，提供可视化界面 | 需要详细分析和报告的场景 |
| **LangChain Evaluators** | ✅ | 与LangChain无缝集成，易于扩展 | 使用LangChain构建的RAG系统 |
| **Promptfoo** | ✅ | 专注于提示词和模型对比评测 | 优化提示词和选择模型 |
| **LlamaIndex Evaluators** | ✅ | 与LlamaIndex无缝集成 | 使用LlamaIndex构建的RAG系统 |
| **HumanLoop** | ❌ | 提供人工标注和评估平台 | 需要大量人工评估的场景 |

## 七、评测最佳实践
1. **自动化与人工结合**：自动化工具用于快速迭代和回归测试，人工评估用于最终验证和复杂问题
2. **持续评测**：将评测集成到CI/CD流程中，每次代码变更都自动运行评测
3. **对比评测**：每次优化后都与之前的版本进行对比，量化优化效果
4. **真实数据优先**：使用真实用户问题作为评测数据集，而不是人工编造的问题
5. **分层定位问题**：先评测检索层，再评测生成层，最后评测端到端和业务层，便于快速定位问题
